## 1. Purpose

Address the three concrete defects v3.2.1 mp2 (committed evidence at
`d9c36ca`) surfaced **without** changing the v3.2 prompt's overall
architecture (R1–R6 + v3.1 rules A–G + gates C9 / C13 / C14 / C15 /
C16):

1. **R4 closure floor — bimodal failure.** PA T3 over-corrected
   (102w against 70-100 band — +2 over ceiling). PD T3 under-floored
   (91w against 100-130 band — -9 below floor). The single mid-band
   anchor + +5 cushion + two-sentence requirement is being applied
   unevenly across age profiles.
2. **R2 fabricated morphology — failed on PD.** Four fabricated /
   wrong-tense items in PD T3 alone: `խորոտալ`, `համբարձլ`,
   `փափախերները`, `պարգևիր`. Same `ձայնուֆով`-class failure family
   as v3.1 mp2. Named-exemplar approach does not generalize.
3. **R3 schwa-stem — partial.** T1 first sentence `Հին կամուրջի վրա`
   ✓ (strict gate held); T1 sentence 3 `կամրջի տակով` ✗ (schwa
   dropped). Spirit-of-rule violated mid-paragraph because R3's
   literal scope is "first sentence only."

Three structural prompt-engineering moves close all three:
- **R4** gains an explicit ceiling guard (do NOT add cushion if
  already above floor+5 / above ceiling).
- **R2** gains a structural verb-conjugation default rule and four
  new forbidden-example tokens from mp2.
- **R3** widens its scope from "first sentence" to "every T1
  sentence containing the place stem."

This slice is the design; the implementation slice is separate and
optional.

## 3. Failure analysis

### 3.1 R4 closure floor — bimodal

**Evidence:**

| Run | Prompt | PA T3 | PA C13 | PD T3 | PD C13 |
|---|---|---|---|---|---|
| v3.1 mp1 | v3.1 | ≈52 | FAIL (-18) | n/a | n/a |
| v3.1 mp2 | v3.1 | ≈55 | FAIL (-15) | ≈50 | FAIL (-50) |
| v3.2 mp1 | v3.2 | ≈66 | FAIL (-4) | n/a | n/a |
| v3.2.1 mp1 | v3.2.1 | ≈72 | PASS (+2 over floor) | n/a | n/a |
| v3.2.1 mp2 | v3.2.1 | ≈102 | PASS but +2 OVER ceiling | ≈91 | FAIL (-9) |

**Root cause:** **prompt wording too weak on the upper-bound side.**
The current R4 (committed at `87665f5`) has only floor-side language:

- "Քայլ 3-ի մարմինը ՊԵՏՔ Է հասնի առնվազն TARGET_WORDS-ի ստորին
  թվին..."
- "Մինչ «Վերջ։»-ը գրելը ինքդ հաշվիր մարմնի բառերը։ Եթե ստորին
  սահմանից առնվազն 5 բառ վերև չես — ՊԱՐՏԱԴԻՐ ավելացրու ԵՐԿՈՒ
  ԱՌԱՆՁԻՆ նախադասություն մինչ ավարտը..."

There is **no clause forbidding the cushion when already above
floor+5**, and **no clause stopping at the upper bound**. The model
adds the cushion sentences whenever in doubt, and the cushion +
mid-band-target compounded on PA mp2 to push past 100. On PD the
opposite: the cushion sentences are *short* (5–7 words) and don't
make up the larger word gap.

**Not a model limitation** — gpt-4o follows length budgets when they
are stated as bounds, not as targets. The current R4 communicates
floor + mid-target but not ceiling, so the model has no signal to
stop on the upper side.

**Not an age-profile band issue per se** — both PA (70-100) and PD
(100-130) are reasonable bands; the issue is the rule's applicability
to the *interval*, not the interval's value.

**Not a scenario issue.**
**Not an evaluation/gate issue** — C13 is floor-only by design, but
the closure-quality concern beyond the gate is the relevant one
(over-band closures feel padded, under-band closures feel rushed).

### 3.2 R2 fabricated morphology — failed on PD

**Evidence (PD T3, v3.2.1 mp2):**

- `պարգևիր` (T3 sentence 3) — wrong tense / mood. Imperative or 2nd-
  person singular form, used where 3rd-person past (`պարգևեց`) is
  required. **Conjugation-default failure.**
- `խորոտալ` (T3 sentence 3) — likely fabricated infinitive; intended
  meaning unclear, possibly "to chirp / sing." No standard EA verb.
  **Fabricated stem.**
- `համբարձլ` (T3 sentence 4) — malformed conjugation; intended
  `համբարձավ` ("ascended"). **Conjugation-default failure.**
- `փափախերները` (T3 sentence 5) — means "fur caps" — wrong word
  entirely. The model probably wanted `փաթեթներ` / `նվերներ` /
  `բարիքներ`. **Wrong-word selection** (lexical, not morphological).

**Root cause:** **example coverage issue + structural rule weakness.**
R2 currently lists two named exemplars (`ձայնուֆով`, `բարենի`) and
two suggested replacements. This pattern works for tokens the model
has *seen* in the prompt but not for novel fabrications. mp2 produced
four new tokens not on R2's list; R2 didn't catch them.

The deeper structural weakness is that R2 does not address the
**common failure pattern** the mp2 evidence shows: the model
fabricates **verb conjugations** (`պարգևիր`, `համբարձլ`) by attaching
plausible-sounding-but-wrong endings to real stems. A categorical
"if uncertain about a verb's form, default to 3rd-person past
`-եց / -ավ / -վեց`" rule would target this directly.

**Not an age-profile issue** — although PD is `age-7-richer` and
permits "թեթև բանաստեղծականություն" (light poeticism), the prompt
also requires "պարզ բառեր." The fabrications are not poeticism;
they are wrong words.

**Not a model limitation** — gpt-4o produces correct Eastern Armenian
when given clear lexical constraints. The R2 rule's structure is the
weak link.

**Not a scenario issue.**

### 3.3 R3 schwa-stem — partial

**Evidence (PD T1, v3.2.1 mp2):**

- T1 sentence 1: `Հին կամուրջի վրա կանգնած էր...` ✓ (schwa
  preserved — every PLACE_STEM letter present).
- T1 sentence 3: `...իսկ կամրջի տակով անցնող փոքրիկ առվակը...` ✗
  (schwa dropped — `կամրջի` instead of `կամուրջի`).
- T2: `...կանգնեցին կամուրջի վրա...` ✓.
- T3: stem absent (T3 doesn't reuse the place by name).

**Root cause:** **prompt wording scope too narrow.** R3's literal
text is:

- "Քայլ 1-ի ԱՌԱՋԻՆ ՆԱԽԱԴԱՍՈՒԹՅՈՒՆՈՒՄ PLACE_STEM-ի ՅՈՒՐԱՔԱՆՉՅՈՒՐ
  տառը պետք է հայտնվի — ՉԸՆԿԱԾ ձայն, ՉՓՈԽԱՐԻՆՎԱԾ տառ, ՉԿՐՃԱՏՎԱԾ
  հիմք։"
- "Քայլ 2-ի և քայլ 3-ի համար այս կանոնը չի կիրառվում"

The model honored the rule's *strict letter* (first sentence only)
and dropped the schwa exactly where the rule explicitly said it
doesn't apply (sentence 3 of the same T1). This is a **scope
specification defect**, not a model failure — the model did exactly
what the prompt said.

**Not an example coverage issue** — the v3.2 prompt already provides
both ALLOWED and FORBIDDEN examples for `հին կամուրջ` (`Հին կամուրջի`
✓ vs `Հին կամրջի` ✗); the model just didn't know to apply them past
the first sentence.

### 3.4 Plan D Armenian naturalness / length-pacing weakness

**Evidence:**

- PD T1 ≈87w against 130-180 floor (-43).
- PD T2 ≈81w against 100-140 floor (-19).
- PD T3 ≈91w against 100-130 floor (-9).
- T3 has multiple garbled phrasings (`հոտը շուրջը համբարձլ ներքևի
  երկար առաջնությամբ`, `բնության փափախերները գալիս ու անցնում`).

**Root cause:** **partly a side-effect of R2 structural weakness**
(garbled phrases compound the brevity); **partly an age-profile band
issue** (PD's `age-7-richer` poetic register encourages the model to
write fewer, denser sentences instead of more, simpler ones — the
opposite of what the band needs for floor compliance).

The R4 fix (per-band cushion + ceiling guard) and the R2 fix
(verb-conjugation default + four new forbidden examples) together
should help PD's body length and naturalness without a separate
PD-specific rule. The age-profile band itself is fine; the issue is
the per-rule wording.

### 4.4 What about the recurring `Մի օր,` mid-paragraph caveat?

PA T1 has had `Մի անգամ,` (v3.2 mp1) or `Մի օր,` (v3.2.1 mp1 / mp2)
mid-paragraph for three consecutive runs. Not a hard-gate fail —
rule A targets the OPENER only.

**Recommendation: do NOT add to v3.2.2.** Reasons:

1. Not a hard gate failure; this is a soft caveat.
2. Adding `Մի օր` to the rule-A forbidden list risks suppressing
   a natural Armenian narrative connector (`Մի օր` is far more
   commonly used in real fairy tales than `Մի անգամ`).
3. The whole `Մի *` family is borderline; banning it broadly would
   over-constrain. Better target opener-only.
4. mp2 + mp1 + v3.2 mp1 caveat is informational; defer until or
   unless it becomes a hard-gate fail or Armenian-quality reviewer
   flags it.

### 4.5 What about old orthography?

v3.1 mp2 had `ունէր` (pre-reform է vs modern ե). v3.2 mp1 / v3.2.1
mp1 / v3.2.1 mp2 do NOT show old-orthography slips on either plan.

**Recommendation: do NOT add an explicit anti-old-orthography rule
to v3.2.2.** Reasons:

1. The defect is no longer reproducing under v3.2.x — three
   consecutive paid runs without `ունէր`-class slips.
2. R1's "Բնական, սահուն, խոսակցական արևելահայերեն" already implies
   modern register; adding a separate orthography rule would risk
   over-explaining.
3. Adding a rule for a non-recurring failure is example coverage
   creep without strong evidence.
4. If v3.2.2 mp1 surfaces an old-orthography slip, defer to v3.2.3.

## 8. Risks

### 8.1 Prompt growth → instruction overload

**Risk:** v3.2.1 prompt is ~220 lines / ~6500 input tokens at T1.
The three v3.2.2 changes add ~21 lines / ~160 Armenian words / ~230
input tokens. Total prompt growth ~3.5 %. The model may reach a
point where it skims later rules.

**Mitigation:** all three changes are surgical extensions of
existing rules, not new rule blocks. No new rule numbers (R7+).
Each change reuses the existing rule's vocabulary and register.
Keep instruction overload acceptable for one more iteration; flag
it as a v3.3-future concern if v3.2.2 surfaces "later rules
ignored" symptoms.

### 8.2 Stronger R2 → prose too plain

**Risk:** the verb-default rule (`use known 3rd-person past form`)
may push the model toward flat narration. The four new
forbidden-token examples may steer the model away from any unusual
verb morphology, including legitimate poetic forms (a real concern
for `age-7-richer` PD which permits "թեթև բանաստեղծականություն").

**Mitigation:** the rule's structure is "if uncertain, default" —
not "always use." A confident model can still use rich verbs. The
mp2 evidence shows the *fabrications* are clustered in PD T3
specifically, so the rule's bite-when-uncertain shape should be
acceptable. Watch v3.2.2 PD output for register flattening; if it
appears, soften to "ՀԱՃԱԽ" instead of "օգտագործիր ... փոխանակ."

### 8.3 Stronger R4 → still sampling-variant

**Risk:** v3.2.1 mp1 (72w) and mp2 (102w) showed wide variance on
the same prompt. The R4 v3.2.2 ladder *adds* ceiling discipline
but doesn't *remove* sampling variance at gpt-4o temperature 1.0.
A v3.2.2 mp1 might land at 88w, mp2 at 95w — both within band but
not necessarily reliably mid-band.

**Mitigation:** acceptance criteria (§ 7) names a band (75–95 PA,
105–125 PD), not a precise target. Reliability across multiple
samples is a separate question that requires a variance pass
(out of scope for v3.2.2). The v3.2.2 design closes a *systematic*
defect (no ceiling guard); it does not promise *low variance*.

### 8.4 PA T2 legacy spatial choice inherited

**Risk:** PA T2 choice-Բ (`մնալ այգում և նայել, թե ինչպես է
արագիլը թռչում տուն`) presupposes the stork is going home, while
the T2 narrative still has the stork undecided. This has shown up
across **all five paid runs** (v3.1 mp1, v3.1 mp2, v3.2 mp1,
v3.2.1 mp1, v3.2.1 mp2). It is a property of
`bakeoff-prompts-v3-1.json`, not the model.

**Mitigation:** out of scope for v3.2.2 (prompt-only). A separate
slice would regenerate PA's T2 choice block to not pre-assume
resolution. Tracked here for awareness only; not blocking v3.2.2.

### 8.5 R3 widened scope may force awkward repetition

**Risk:** the current R3 scope (first sentence only) gives the
model permission to refer to the place differently in subsequent
sentences (e.g. with pronouns, or with shortened forms). Forcing
the schwa-not-dropped form *everywhere* the stem appears in T1
might encourage the model to repeat `հին կամուրջի` verbatim too
many times.

**Mitigation:** the rule allows any case-marked form
(`կամուրջի վրա`, `կամուրջի տակ`, `կամուրջի մոտ`, `կամուրջի վրայով`,
`կամուրջը` in nominative) — the model has variety. Pronouns
(`այնտեղ`, `դրա վրա`) are still allowed because they don't
contain the stem. The constraint only bites when the model
explicitly uses the place name a second time. Watch v3.2.2 PD T1
for awkward repetition; if it appears, scope to first two
sentences only.

### 8.6 Single-sample evaluation

**Risk:** even after v3.2.2 mp1 + mp2 land cleanly, that's still
N=1 per scenario. The mp1/mp2 closure variance under v3.2.1
(72→102w) is enough warning that a "pass on first try" doesn't
prove reliability.

**Mitigation:** v3.2.2 is not the last word; it's the next safe
slice. A follow-up variance pass (multi-sample on temperature 0.7
or 0.5) is on the v3.3+ horizon. Not in scope here.
