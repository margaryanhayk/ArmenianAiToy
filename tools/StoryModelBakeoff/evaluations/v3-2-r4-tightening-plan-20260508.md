Close the **only persistent hard FAIL** in the v3.2 writer
prompt's first paid run: **C13 closure length** at Turn 3 of
Plan A (committed v3.2 mp1 evidence at `54c391f`). Across three
paid OpenAI gpt-4o runs the gap has narrowed monotonically but

"tighten R4 only, no R2 example tweak." Decision A (no edit, run

## 5. R4 change design (the diff)

### 5.1 Where in the file

`tools/StoryModelBakeoff/system-prompt-v3-2.txt`, the
`ՆՈՐ R4 — ՓԱԿՄԱՆ ԵՐԿԱՐՈՒԹՅԱՆ ԽԻՍՏ ՀԱՏԱԿ` block. Before the

### 5.3 What each move does

1. **Header tag** (`STRICTER v3.2 + r4-tighten v3.2.1`) — a
   one-line label that lets future evidence files refer to
   this rule version without ambiguity. Mirrors the existing
   convention (`R1 — STRICTER v3.2`, `R2 — NEW v3.2`,
   `R3 — STRICTER v3.2`, `R5 — STRICTER v3.2`, `R6 — NEW v3.2`).

2. **"Absolute minimum, not the target"** clause appended to
   the first bullet — closes a known weakness of the original
   wording: the model treated `70` as a soft floor and stopped
   at 66. The clause makes the role of the floor explicit.

3. **NEW mid-band-target bullet** — `ԱՆՎՏԱՆԳ ԹԻՐԱԽԸ միջակայքի
   մեջտեղն է` ("the safe target is the middle of the range")
   with explicit numeric anchors `≈ 80` for 70-100 and `≈ 110`
   for 100-130. Shifts central tendency upward from "hit the
   floor" to "land in the middle." Per-band numbers, not a
   generic "+10w," because PA and PD have different bands and
   the mid-point varies.

4. **Strengthened count-and-add bullet** — three changes:
   - Trigger now fires when "less than +5 above floor"
     instead of "below floor." This is the safety cushion that
     stops 66w-style near-misses.
   - Replaces "1-2 sentences" (soft) with "TWO SEPARATE
     sentences" (hard). The model previously could interpret
     "1-2" as "0 if I think I'm close enough"; the hard count
     removes that escape.
   - Specifies WHAT each of the two sentences carries —
     sentence 1 is one in-scene sensory image, sentence 2 is
     one small calm character reaction. Both are exact patterns
     R5 already authorizes (R5 says "concrete present-moment
     image, character action, place light/sound/scent"). This
     reuses an authorized vocabulary rather than introducing a
     new one.
   - Forbids merging them into one subordinate clause —
     blocks the `որպես փոքրիկ նվեր` / `որոշեց նվիրել` style
     compression that R6 has been chasing.

## 8. Risks

1. **Prompt-length growth.** ~80 added Armenian words ≈ ~120
   added input tokens per call × 3 calls per scenario × 2
   scenarios on a future mp2 = ~720 added input tokens, ≈
   $0.002 added spend at gpt-4o pricing. **Bounded; trivial.**

2. **Model may still ignore the floor.** A statistical model
   is not a deterministic word-counter. The cushion ("+5
   above") and the structural specificity (two sentences, each
   with a defined role) reduce but do not eliminate this risk.
   **Mitigation: empirical mp2 will measure it.**

3. **Padded closures.** Forcing two extra sentences when the
   body is short risks a stilted tail. Mitigation: each
   sentence has a constrained role (sensory image / small
   reaction) that R5 already considered natural; the
   forbid-merge clause stops the model from compressing them
   back into one subordinate clause.

4. **Mid-band target may overshoot the upper bound on PA.** PA
   ceiling is 100; mid-target is 80; with the two-sentence
   cushion the body could reach 100–110. C13 only checks the
   floor, not the ceiling, so the upper bound is not a hard
   gate. **Acceptable.**

5. **PD remains untested under v3.2 at all.** This slice does
   not change that — it only fixes the v3.2 mp1 failure.
   PD R1 (cross-language leak) and PD R3 (schwa) load-bearing
   tests still require mp2.

6. **R2 morphology candidates persist.** `փայլալիք` and
   `փռփռացնելով թևերը` from v3.2 mp1 are not addressed by this
   slice. They are not on a hard gate; deferring to v3.3 keeps
   the mp2 signal clean. If mp2 reproduces the same family on
   PA, v3.3 should append `«փայլալիք»` to R2's example list.
